# AI 역량평가 연습

첨부된 평가 화면을 참고한 한국어 객관식 연습 사이트. HTML/CSS/JavaScript와 Node.js 서버로 구성되며, 어시스트는 OpenAI API의 `gpt-4o-mini`를 사용합니다.

## 로컬 실행

```sh
cd ai-assessment-practice
# Node.js 22.16 이상
# .env에 OPENAI_API_KEY=실제키 입력 (.env.example 참고)
npm start
```

http://127.0.0.1:4173 에서 실행합니다. `npm test`로 생성 문항의 정답, 자료 계산, 채점 규칙을 검증합니다.

## 메뉴 및 동작

- AX 직무역량평가: KT 2026년 대졸신입 B2B컨설팅&세일즈 공고만 참고. 기본 직무역량 5문제 + AX 문제해결 5문제. 두 영역의 정답 수와 점수를 별도로 표시합니다. 자기소개서와 지원자 개인정보는 사용하지 않습니다.
- AI 활용평가: 간식 설문, 구독 최적화, 상품 규정, 고객 의견, B2B 캠페인, 협력사 구매는 각 4문제. 교육 효과성과 개선 전략은 8문제.
- AI 지식평가: 21개 문항 유형 중 10개를 선정합니다.
- 전체 169개 문항 유형에서 메뉴별 세트를 선택하고, 수량·예산·비율·문서 조건·보기 등을 생성합니다. 신규 세트에서는 질문 주제와 자료가 함께 달라집니다. 현재 출제 문항은 모두 4지선다이며 상 난도로 설계했습니다.
- 자료 뷰어는 가상의 표·정책·RFP·회의 기록을 HTML로 렌더링합니다. 자료별 텍스트 다운로드, 전체 자료 묶음, 선택 자료와 질문의 AI 입력용 텍스트 다운로드를 제공합니다.
- 어시스트는 `gpt-4o-mini`로 질문 의도·문제·선택 자료·이전 대화를 분석합니다. 자료가 있는 평가에서 세트당 응답 성공 10회까지 사용할 수 있습니다.
- 답안 선택, 문제 이동, 다시 풀 표시, 초기화, 미응답 확인, 100점 환산, 문제별 정답·해설을 제공합니다.

평가 시작과 채점 후 새 문제 생성은 자료와 문제를 새로 구성합니다. 같은 평가 안의 문제 이동은 답안과 자료를 유지합니다. 새로고침하면 현재 탭에 저장된 평가·답안·메모·시간·대화를 복원합니다. 출제 이력에서 미출제 유형을 우선하고 이후 출제 횟수가 적고 오래된 유형을 선택합니다. 업무상황의 연속 세트는 유형이 겹치지 않습니다. 유한한 169유형을 소진하면 복습하며 무한한 LLM 문항 생성은 아닙니다.

## GitHub Pages

`dist/`가 배포 대상이며 모든 리소스 경로는 상대 경로입니다. 새 저장소의 `main`에 코드를 푸시하고 Settings → Pages → Source를 GitHub Actions로 설정하면 `.github/workflows/pages.yml`이 테스트 후 정적 파일을 배포합니다. GitHub Pages에서는 서버 API가 실행되지 않아 AI 어시스트는 사용할 수 없습니다. 실제 AI는 `npm start`로 실행한 로컬 페이지에서 사용하세요. 공개 배포에는 저장소와 소스 코드도 공개될 수 있습니다. 정답도 브라우저 소스에 포함되므로 연습용으로만 사용하세요.

## 가이드에 맞춘 연습 흐름

1. 메뉴 선택 → 시작 안내와 연습 시간 선택.
2. 사전 체험(별도 2문항, 시간 제한·채점 없음) 또는 본 연습 시작.
3. 보기 선택 시 답안 저장, 파란 체크 표시. 문제 이동·수정과 노란 깃발 표시 가능.
4. 문제별 메모와 내 답안 현황. 종료 전 미응답을 검토하고 해당 문제로 이동.
5. 최종 제출 후 답안 수정 잠금과 정답·해설 제공. 제한 시간 종료 시 현재 답안을 자동 제출.

어시스트는 자동 맥락/문제 번호 선택, 자료별 AI 질문에 추가, 질문 1,000자, 30초 재전송 대기, 세트당 10회, 최근 10개 대화 쌍 표시를 지원합니다. 응답 성공 후 첨부를 해제하며 이전 첨부는 후속 대화 맥락으로 전달합니다. 실제 LLM을 사용합니다. 모델 토크나이저 기반의 공식 20,000토큰 제한은 재현하지 않으며, 서버에서 전체 메시지 JSON 100,000자와 HTTP 요청 1MB를 제한합니다. 파일 자료는 업무상황별 30~42개의 가상 문서를 제공합니다.

본 연습의 지문·보기·문서 뷰어에서 텍스트 선택/복사를 제한합니다. 이는 UI 조작 연습이며 실제 시험의 보안·감독 시스템이 아닙니다. 웹캠·화면공유·모니토는 요청하지 않습니다. 기존의 객관식만 연습하는 범위와 dark 테마를 유지합니다.

현재 답안·연습 상태는 탭 단위 sessionStorage에, 메뉴별 출제 이력은 브라우저 localStorage에 저장합니다. AI 요청 시 지문·문제·보기·질문·첨부 원문·이전 AI 대화를 로컬 서버를 통해 OpenAI로 전송합니다. 정답·해설·메모·선택 답안·출제 이력은 API 요청에 포함하지 않습니다. 서버는 대화를 파일에 저장하지 않습니다. 출제 이력은 브라우저·기기 간 동기화되지 않습니다. 브라우저에서 저장이 차단되면 화면에 자동 저장 불가를 표시합니다. 제한 시간은 종료 시각 기준으로 계산하여 새로고침이나 메뉴 이동으로 시간이 초기화되지 않습니다.


AI 활용평가와 AX 평가의 어시스트 패널은 데스크톱에서 기본으로 표시됩니다. 패널을 닫아도 지문·각 문제 옆·하단의 AI 어시스트 버튼으로 다시 열 수 있습니다. 모바일에서는 문제를 가리지 않도록 패널을 접고 하단 버튼으로 여는 방식을 사용합니다. 이전 버전에서 저장된 초기 닫힘 상태는 첫 복원 시 정상 표시 상태로 전환합니다.

배포 자산에는 버전 쿼리를 사용해 이전 JavaScript·CSS 캐시가 수정 화면을 가리지 않게 합니다. 이후 배포 시 index.html과 JS import의 버전 값을 함께 갱신하세요.

## 자료 및 출제 고도화

업무상황 수와 세트별 문항 수는 유지했습니다. 상황마다 6개 후속 검토 기록, 5개 지표가 포함된 운영대장, 지표 정의서, 검토 업무목록, AI 검토 요청·회의록을 추가했습니다. 기존 자료와 후속 자료의 모집단·기간을 명시하여 서로 다른 기록을 잘못 합산하지 않도록 했습니다.

| 메뉴 | 문항 유형 | 세트 문항 | 자료 파일 |
|---|---:|---:|---:|
| 간식 설문 | 18 | 4 | 30 |
| 구독 최적화 | 18 | 4 | 32 |
| 상품 규정 | 18 | 4 | 32 |
| 고객 의견 | 18 | 4 | 30 |
| 캠페인 | 18 | 4 | 30 |
| 협력사 구매 | 18 | 4 | 30 |
| 교육 효과성 | 18 | 8 | 32 |
| AX 직무역량 | 22 | 10 | 42 |
| AI 지식 | 21 | 10 | 0 |

기존 기초 문제의 출제를 중단하고 **심화 169유형(수리 추론 96·조건부 판단 73)**으로 교체했습니다. 지식평가도 21유형으로 늘려 모든 메뉴에서 연속 세트의 유형 중복을 방지합니다. 전체 유형 소진 후에는 복습하며 숫자와 문서만 바뀐 같은 유형은 별도 신규 유형으로 세지 않습니다. AX는 기본 직무역량과 AX 문제해결 각각 11유형에서 5개씩 선택합니다. 이력 저장이 차단되면 실행 중 메모리 이력으로 계속 동작합니다. 사전 체험 세트도 출제 이력에 반영됩니다.

채점 후 정답 이유, 근거 문서·기록 위치, 보기별 해설을 표시합니다. 오답에는 분모 혼동, 매몰비용 포함, 고정비 누락, 임계값 오류비용, 모집단 구성과 인과관계 혼동 등 구체적인 오류를 반영했습니다. 보기 순서를 바꿔도 정답과 오답 이유의 연결을 유지합니다.

AI 패널의 **전체 자료 첨부**로 문서 전체를 선택하거나 개별 자료를 고를 수 있습니다. **선택 자료·질문 내려받기**는 정답·해설 메타데이터를 제외한 전체 원문과 객관식 질문을 UTF-8 TXT로 저장합니다. 실제 LLM에 파일을 입력해 검토할 수 있습니다. 앱 자체 어시스트도 실제 LLM을 호출하며 선택 자료는 발췌 없이 전체 원문을 전달합니다.

## 상 난도 출제 기준

- 단일 비율 계산·규칙 복사·O/X 대신 복수 조건과 여러 단계의 계산을 요구합니다.
- 예: 모집단 가중 추정→포장·재고 발주, 인원·기능·용량 혼합 구독→중복 청구와 손익분기, 집단 구성 보정→차이의 차이, 검수·실패 재처리→현금화 가능한 AX 편익.
- 판단형은 실행 가능한 대안 사이에서 목표·기한·권한·증빙·위험의 차이를 평가합니다. 계산이 맞더라도 적용 범위나 필수조건을 놓치면 오답입니다.
- 수리형은 네 가지 규모 변형 전체에서 보기 유일성을 확인하며, 최저비용 문제는 가능한 대안을 열거해 정답을 검증합니다.
- 기업의 수리 추론·상황 판단 평가에서 쓰는 설계 관점을 참고했습니다. 상 난도는 자체 설계 등급이며 실제 응시자의 정답률이나 특정 기업 시험과의 동등성으로 보정한 값은 아닙니다.

저장된 이전 연습의 답안과 자료는 유지합니다. 메뉴에서 이전 난이도임을 표시하며 **새 연습**부터 상향 문항이 적용됩니다. 기존 기초 자료도 문서 묶음에 남아 있고, 심화 원장과 판정조건에는 별도 모집단·기간임을 표시합니다.

## 실제 AI 어시스트 설정과 사용

1. 기존 `.env`에 `OPENAI_API_KEY=실제키`를 입력합니다. 키는 브라우저 코드에 넣지 않습니다. `.env`는 Git 추적에서 제외됩니다.
2. `npm start`로 실행하거나 이미 실행 중인 서버를 재시작한 뒤 http://127.0.0.1:4173 을 새로고침합니다. 포트는 `.env`의 `PORT`로 변경할 수 있습니다.
3. 패널에 `gpt-4o-mini · 실제 AI`가 표시되는지 확인합니다. 이 표시는 키 설정 여부이며 유효성은 첫 API 요청에서 확인됩니다.
4. 필요한 자료를 첨부하고 자연스럽게 질문합니다. “이 자료 요약해줘”, “3번의 두 대안을 총비용으로 비교해줘”, “왜 이 분모를 쓰는 거야?”처럼 질문할 수 있습니다. 명시한 문제를 우선하며 “왜?” 같은 후속 질문은 직전 대화의 대상을 유지합니다. 새 문제를 선택하면 새 선택을 따르고, 그 외에는 선택 문제·현재 화면 순으로 참고합니다. 요약 요청은 그대로 처리합니다.
5. 답변 형식은 자동, 자료 요약, 계산 검증, 보기·대안 비교, 보고서·개선안, 풀이 힌트 중 선택할 수 있습니다. 추가 제약조건에 길이·표·정답 공개 여부 등을 입력합니다.

기본 지침은 문서명·기록 위치 인용, 계산식·단위·분모 표시, 필수조건 검토, 사실·가설·미확인 구분입니다. 정답 번호는 자료에서 추론하며 앱의 정답표를 제공하지 않습니다. API 인증·한도·연결 실패 시 오류를 표시하고 횟수·질문·첨부를 유지합니다. 중복 요청을 차단하고 성공 응답 후 30초 대기합니다. 질문은 1,000자, 대화는 최근 10쌍입니다. 이 사용 제한은 로컬 연습 UI 기준이며 공식 시험 보안 통제가 아닙니다.

API 형식은 [OpenAI 공식 Chat Completions 문서](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)를 참고했습니다. 사용자 공유 대화 URL은 403/접근 오류로 본문을 확인하지 못했으며, 저장소의 업무 상황·예시를 기준으로 구성했습니다. 실제 시험의 내부 시스템 프롬프트나 동등한 응답 품질을 재현한다고 보장하지 않습니다.

문제별 근거 문서명·기록 위치와 전체 파일명 목록을 전달하여 심화 원장과 기초 예시를 구분합니다. 파일명 목록만으로 원문을 읽었다고 주장하지 않으며 필요한 자료의 첨부를 요청합니다. 계산값이 보기에 없으면 조건을 다시 검토하고 불일치를 표시하도록 지시합니다. 일반 개념 설명은 사례 수치와 구분하며 이전 AI 답변도 원문에서 재확인합니다.

`.gitignore`는 `.env`와 환경별 변형, 개인 키 파일, 로그, 의존성, 테스트 산출물과 `private/`, `local-data/`를 제외합니다. 공개할 수 없는 교재·원본 자료는 두 디렉토리에 보관하세요. 빈 `.env.example`과 사이트 실행에 필요한 `dist/`는 추적합니다. 기존 추적 파일에는 ignore 규칙이 소급 적용되지 않으므로 push 전 `git status --short`와 변경 내용을 확인하세요.
